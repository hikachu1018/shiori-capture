# しおり Capture 0.5.0

Kindleの表示画面をAndroidまたはWindows 11で読み取り、日本語の本文を本棚へ保存します。Galaxyアプリでは章ごとにRSVP読書できます。PC版とGalaxy版は同じWi-Fi上で同期し、PCが起動中でGalaxyのアプリが開いている間だけ通信します。読書と保存済み本文の閲覧はオフラインで動作します。Android 11以降が必要です。

## Windows版と同期

1. Amazon公式ページから新しい[Kindle for Windows](https://www.amazon.co.jp/kindleapps)をインストールし、読み取る本を開きます。旧版Kindle for PCには対応しません。PC版のZIPを展開し、`ShioriCapture/ShioriCapture.exe` を起動します。
2. Windows版「しおり Capture PC」の「新しい本」で本棚に本を作り、「撮影・再開」を押します。5秒以内にKindleの読書画面を前面にします。Page Downで画面を送り、同じ画面が続くと停止します。「一時停止」で保存済み画面を残せます。撮影を制限する本では処理を中断します。
3. PC版で画面ごとの本文、章名、表紙・挿絵を確認します。画面ごとのOCR本文を修正できます。誤認識や目次と一致しない章は手動で直してください。
4. 両端末を同じWi-Fiへ接続し、PC版の「同期の接続情報」を開きます。Galaxy版「本棚の管理」→「PCと同期」でQRを読み取ります。QRが使えない場合は、PCに表示される接続情報を貼り付けます。初回ペアリング後は両アプリを開いている間に自動同期します。

PC版は `desktop` 以下にあります。開発時はPython 3.12で `desktop/requirements.txt` をインストールし、リポジトリを作業ディレクトリとして `PYTHONPATH=desktop python -m shiori.app` で起動します。Windows配布用ZIPは `desktop/build.ps1` で作成します。OCRモデルを含めるため、ビルド環境にはインターネット接続が必要です。保存データとペアリング用の証明書はWindowsの `%LOCALAPPDATA%\ShioriCapture` に置きます。GitHubには含めません。

配布版のPC ZIPは[0.5.0 Release](https://github.com/hikachu1018/shiori-capture/releases/tag/v0.5.0)から取得します。ZIPを展開し、フォルダー内の `ShioriCapture.exe` を起動してください。OCRモデルを同梱するため、ZIPは約440MBです。

本を削除すると次回同期で両端末の本棚から隠れ、30日以内は復元できます。両端末で同じ本を変更した場合、Galaxy側の変更は「競合した変更」という別の本として残ります。Galaxy版の「PCと同期」→「競合した変更を選ぶ」で両方の本文冒頭を比較し、残す版を選べます。別々に撮影した同じ本は、PC版の「同じ本を統合」で内容を確認してから統合できます。

0.3.2では本棚と撮影設定をタブに分け、読書画面の操作と進捗表示、章編集画面の配置を見直しました。撮影や読書のデータ形式は0.3.1から変えていません。

0.3.3ではKindleの画面下部に表示される「章を読み終えるまで: ○分 ○％」をOCR本文から除外します。0.3.2以前に保存した本も、アプリ更新後に本棚を開くと該当文字列をデータベースから削除します。章の境界と読書位置は保持します。以前に書き出したEPUB・PDFには変更が反映されないため、必要なら更新後に書き出し直してください。

0.3.4では本棚に本の名前での検索と並べ替えを追加しました。各本の「その他」から削除できます。削除前に確認画面を表示し、削除するとアプリ内の本文・章・読書位置が消えます。書き出し済みのEPUB・PDFは残ります。

0.3.5ではOCR画面の下端10％にある文字行を本文へ入れず、残りの行にも「章を読み終えるまで」という表示があれば数字・記号が欠けていても除外します。すでに取り込んだ本も、更新後に本棚データベースを開いたときに再処理します。書き出し済みのEPUB・PDFには反映されないため、必要なら再度書き出してください。

0.3.6では撮影した目次が複数画面に分かれていても項目を収集し、本文の章見出しと表記を照合して目次の章名を使います。章冒頭との一致が確認できた場合は、目次と短い表紙画面を読書本文から除外します。保存済みの本も自動で再検出しますが、手動編集した章は上書きしません。章編集画面の「目次から章を再検出」で任意の本を再処理でき、一致しない章も「目次の項目から章を追加」で目次の章名と本文の開始段落を結び付けられます。スクリーンショットからKindleのリンク先情報は取得できないため、対応する本文の冒頭がまだ保存されていない場合、章の開始位置は決められません。

0.4.0では章追加の画面選択を1回のタップで確定できるようにしました。撮影した表紙と挿絵を圧縮画像として端末内に保存して読書画面に表示し、表紙のOCRから本の名前を自動設定します。本棚の「本文と画像を確認」で画面ごとのOCR結果、読書本文から除外した文字、保存画像を確認できます。目次と画像ページのOCR文字は読書本文から除外します。表紙に文字がない場合や検出できない場合は仮の本名を付けるため、本棚から変更してください。

0.4.1では、黒背景で文字の少ないタイトルページを画像として判定できない問題を修正しました。出版社や訳者の表記があるタイトルページを本名の取得に使い、OCR文字は読書本文から除外します。0.4.0で保存した本も更新時に再判定して本名と本文を修復します。ただし、保存していなかった元画像は復元できません。本文ページの文字認識自体を改善するには、誤認識した本文画面の例を確認する必要があります。

## 使い方

1. アプリでユーザー補助サービス「しおり Capture」を有効にします。
2. 縦書き／横書き、ページ送りの方向、準備時間、ページ送り後の待ち時間を選びます。本の名前は空欄にすると表紙から自動取得を試みます。
3. 「撮影を開始」を押し、準備時間中にKindleで目次と本文を開きます。目次も撮ると章名の検出に役立ちます。
4. 初回は3画面ほどで「一時停止」を押し、本棚の「本文と画像を確認」でOCR本文、画像、章立てを確認します。長い本も本棚の「撮影を再開」から同じ本へ追記できます。再開時はKindleで保存済みの最後の画面か、その次の画面を開きます。同じ画面は読み飛ばします。
5. 本棚から章を選んで読みます。読書画面では再生・一時停止、速度変更、前後移動、章選択、前回位置からの再開ができます。自動再生は章末で止まります。
6. 「章を編集」の「章を追加」から開始画面を選ぶと、その画面の先頭に章を追加します。同じ位置に章がある場合は段落を選べます。章名と開始位置も変更できます。
7. 本棚では本の名前で検索し、最近使った順・タイトル順・登録順で並べ替えられます。「その他」→「本を削除」で不要な本を削除できます。撮影中の本は一時停止してから削除してください。

各画面のOCR本文はSQLiteへ、検出した表紙・挿絵の画像はアプリ専用領域へ保存します。一時停止やアプリの中断後も保存済み分は「途中まで」の本として本棚に残ります。OCRの処理待ちが終わってから一時停止するため、保存完了の表示を確認してください。章を手動編集した後に撮影を再開しても、その章立てを残します。画像の自動判定、OCRの読み順、ルビ、図表、段組みは手動確認が必要です。以前に取り込んだ本の画像は元のスクリーンショットが残っていないため復元できません。

## 取り込みと書き出し

旧版0.2の「章付きEPUB」を本棚に取り込めます。旧版のPDFや任意のEPUBには対応しません。

本棚の本カードで「その他」→「EPUB・PDFを書き出す」を選んだときだけ、編集後の章立てを持つEPUBと、本全体を収めた単一のテキストPDFを作ります。現時点で保存画像はアプリ内読書と確認画面に表示され、EPUB・PDFの書き出しには含まれません。書き出し先はAndroidのフォルダ選択画面で指定します。本棚のデータはアプリ専用領域にあるため、アンインストール前には必要な本をEPUBに書き出してください。

## Galaxyへのインストール

Galaxyの64ビットARM端末向けAPK（約22MB）は、[GitHub Raw直接リンク](https://raw.githubusercontent.com/hikachu1018/shiori-capture/downloads/shiori-capture-0.5.0-galaxy-arm64.apk)からダウンロードできます。以前のGalaxyではこの配布経路で保存できたことを確認しました。保存したAPKは「マイファイル」から開いてインストールします。必要に応じて、使用したアプリに「不明なアプリのインストール」を許可します。

GitHub ReleasesのAPK単体は以前Galaxyで保存が完了しなかったため、別経路の直接リンクを用意しました。Galaxy向けAPKを直接保存できない場合は[RawのZIP版](https://raw.githubusercontent.com/hikachu1018/shiori-capture/downloads/shiori-capture-0.5.0-zip-download.zip)を「マイファイル」で展開してください。ZIPにはGalaxy向けAPKが入っています。

端末のCPUが分からない場合は、[全機種向けAPKの別経路直接リンク](https://raw.githubusercontent.com/hikachu1018/shiori-capture/downloads/shiori-capture-0.5.0-universal.apk)を使えます。

0.3.0からは同じ署名鍵で上書き更新でき、本棚のデータも引き継ぎます。さらに古い試用版と署名が異なり「更新できません」と表示された場合は、旧版の章付きEPUBを端末の共有フォルダへ書き出し、旧版をアンインストールしてから0.5.0をインストールしてください。アンインストールで旧版のアプリ専用データは消えるため、先にEPUBが端末の共有フォルダに残っていることを確認します。

## 開発とビルド

JDK 17、Android SDK API 35とBuild Tools 35.0.0を使います。`local.properties` に `sdk.dir` を設定し、`./gradlew --no-daemon testDebugUnitTest assembleRelease` を実行します。Windowsは `gradlew.bat` を使います。GitHub Actionsも同じテストとビルドを行います。

公開用APKの署名鍵はリポジトリ外で保管し、GitHub Releasesに署名済みAPKとSHA-256を掲載します。ソースには撮影した本のデータや署名鍵を含めません。検証状況は `VALIDATION.md` を参照してください。
